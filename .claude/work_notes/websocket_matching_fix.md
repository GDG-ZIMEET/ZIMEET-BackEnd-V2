# [개선 작업] 웹소켓 비정상 종료 시 매칭 큐 정합성 확보

## 1. 이슈 배경 및 문제 정의
현재 지밋(ZIMEET)의 매칭 시스템은 유저가 매칭 큐에 진입한 후, 웹소켓 연결을 통해 상태를 실시간으로 전달받습니다. 하지만 다음과 같은 상황에서 **상태 불일치(State Inconsistency)**가 발생합니다.

- **문제 상황**: 사용자가 매칭 대기 중 브라우저를 닫거나, 앱 강제 종료, 네트워크 단절 등으로 웹소켓 연결이 끊어지는 경우.
- **현상**: 서버는 웹소켓 연결이 끊겼음을 인지하지 못하고, 유저는 `MatchingQueue`에 여전히 `WAITING` 상태로 남아있음.
- **결과**: 이미 이탈한 '유령 유저(Ghost User)'와 다른 정상 유저가 매칭이 성사되어, 정상 유저가 빈 채팅방에 남겨지거나 매칭 로직이 꼬이는 비즈니스 오류 발생.

## 2. 해결 방안 (Technical Implementation)
Spring의 웹소켓 이벤트 리스너를 활용하여 세션의 생명주기와 도메인의 상태를 동기화합니다.

### 작업 단계
1.  **WebSocketEventListener 구현**: `SessionDisconnectEvent`를 구독하는 리스너 클래스 생성.
2.  **사용자 식별**: `StompHeaderAccessor`를 통해 연결 종료된 세션의 `Principal`(userId) 정보를 추출.
3.  **상태 복구 로직 실행**:
    *   해당 유저가 현재 매칭 큐(`MatchingQueue`)에서 대기 중인지 조회.
    *   대기 중이라면 큐에서 삭제 처리.
    *   매칭 시도 시 차감된 티켓(아이템)을 다시 환불 처리(재화의 원자성 보장).
4.  **트랜잭션 관리**: 큐 삭제와 티켓 환불이 하나의 단위로 처리되도록 서비스 레이어에서 트랜잭션 처리.

## 3. 이력서 작성 예시 (Resume Bullet Points)

기존 이력서의 **지밋(ZIMEET)** 프로젝트 성과 부분에 아래 내용을 추가하는 것을 추천합니다.

### [추천 문구 1: 트러블슈팅 강조형]
> **웹소켓 세션 유실로 인한 '유령 유저(Ghost User)' 잔존 이슈 해결 및 매칭 신뢰도 제고**
> - 네트워크 단절 등 비정상 종료 시 매칭 큐와 실제 접속 상태가 불일치하여 발생하는 오매칭 현상 발견
> - `SessionDisconnectEvent` 기반의 후처리 핸들러를 구현하여, 세션 종료 시점에 매칭 큐 자동 이탈 및 소모 재화(티켓) 환불 로직을 구축하여 데이터 정합성 100% 확보

### [추천 문구 2: 시스템 안정성 강조형]
> **웹소켓 생명주기를 활용한 실시간 동시성 상태 동기화 구현**
> - 세션 종료 이벤트를 감지하여 분산 환경(Redis/DB)의 매칭 큐 상태를 즉각 동기화함으로써 좀비 세션으로 인한 리소스 낭비 예방
> - 예외 상황(강제 종료 등)에서의 사용자 재화 복구 로직을 설계하여 비즈니스 서비스 안정성 강화
