# [개선 작업] 웹소켓 비정상 종료 시 매칭 큐 정합성 확보

## 1. 이슈 배경 및 문제 정의
현재 지밋(ZIMEET)의 매칭 시스템은 유저가 매칭 큐에 진입한 후, 웹소켓 연결을 통해 상태를 실시간으로 전달받습니다. 하지만 다음과 같은 두 가지 핵심적인 **상태 관리 및 보안 취약점**이 존재합니다.

### 1-1. 비정상 종료 시 '유령 유저(Ghost User)' 잔존 현상
- **문제 상황**: 사용자가 매칭 대기 중 브라우저를 닫거나 앱 강제 종료, 네트워크 단절 등으로 웹소켓 연결이 끊어지는 경우.
- **현상**: 서버는 웹소켓 연결이 끊겼음을 인지하지 못하고, 유저는 `MatchingQueue`에 여전히 `WAITING` 상태로 남아있음.
- **결과**: 이미 이탈한 유저와 다른 정상 유저가 매칭이 성사되어 서비스 신뢰도 저하 및 재화 손실 발생.

### 1-2. 매칭 Topic 구독(SUBSCRIBE) 시 인가(Authorization) 검증 누락
- **문제 상황**: 특정 매칭 채널(`/topic/matching/{groupId}`)에 대한 구독 권한 검사 부재.
- **현상**: 악의적인 사용자가 다른 사람의 `groupId`를 추측하거나 가로채어 해당 채널을 구독 가능.
- **결과**: 타인의 매칭 정보(유저 개인정보 등)가 담긴 패킷을 무단으로 수신할 수 있는 보안 취약성 존재.

## 2. 해결 방안 (Technical Implementation)

### 2-1. WebSocket 세션 핸들러를 통한 상태 동기화
1.  **WebSocketEventListener 구현**: `SessionDisconnectEvent`를 구독하는 리스너 클래스 생성.
2.  **사용자 식별**: `StompHeaderAccessor`를 통해 연결 종료된 세션의 `Principal`(userId) 정보를 추출.
3.  **상태 복구 로직 실행**: 매칭 큐 자동 이탈 및 소모 재화(티켓) 환불 처리로 데이터 정합성 보장.

### 2-2. SUBSCRIBE 단계의 인터셉터 권한 검증
1.  **StompHandler 확장**: `preSend` 메서드에서 `StompCommand.SUBSCRIBE` 메시지 가로채기.
2.  **권한 검사**: 구독하려는 `Destination` 경로에서 `groupId`를 추출하고, 현재 요청을 보낸 `userId`가 해당 그룹의 참여자인지 확인.
3.  **접근 제어**: 권한이 없는 경우 예외를 발생시키거나 `return null`을 통해 구독을 원천 차단.

## 3. 이력서 작성 예시 (Resume Bullet Points)

### [추천 문구 1: 안정성 및 보안 통합형]
> **웹소켓 세션 관리 체계 고도화: 비정상 종료 대응 및 토픽 구독 인가 처리**
> - **[안정성]** `SessionDisconnectEvent` 기반 리스너를 구축하여 비정상 세션 종료 시 매칭 큐 즉각 이탈 및 재화 자동 환불 로직 구현 (정합성 이슈 0건 달성)
> - **[보안]** STOMP 인터셉터를 활용하여 채널별 구독 권한 검증 기능을 도입, 불특정 다수의 매칭 데이터 무단 탈취 위험 원천 차단

### [추천 문구 2: 트러블슈팅 강조형]
> **실시간 통신 계층과 도메인 계층 간 상태 불일치 해결 및 데이터 보호**
> - 웹소켓 생명주기와 매칭 프로세스의 연동을 통해 '유령 유저' 잔존으로 인한 오매칭 문제를 해결하고 사용자 경험 개선
> - 보안이 취약한 Topic 구독 방식에 인가 로직을 추가하여 민감한 개인정보가 포함된 매칭 데이터에 대한 접근 제어 강화
